Ты — разработчик покерного бота для ClubGG (кэш NLH, стол до 6 игроков, Android). Бот: cv2-распознавание + табличная стратегия (БЕЗ ИИ в игровом цикле — принципиально). Код в текущей директории: main.py (цикл), strategy.py (решения), hand_evaluator.py (сила руки), table_state.py (кадр), panel.py (веб-панель, http://127.0.0.1:8090, только stdlib, Windows), devices.json (конфиг устройств, panel.py его пишет).

ГЛАВНОЕ ТРЕБОВАНИЕ ПОЛЬЗОВАТЕЛЯ: каждая новая возможность настраивается ВКЛ/ВЫКЛ через панель (devices.json → UI). Пользователь не сисадмин: нужны простые переключатели и пресеты, а не редактирование кода.

ТЕКУЩАЯ АРХИТЕКТУРА НАСТРОЕК:
- panel.py: devices.json хранит per-устройство: name, chart, aggression, defense, stack. При старте бота panel.py вызывает main.py с флагами --aggression/--defense/--chart/--stack/--name. Настройки применяются ТОЛЬКО при перезапуске бота.
- strategy.py: Chart.settings (DEFAULT_SETTINGS) — open_size_bb, three_bet_mult, cbet_pot, nuts_pot, semi_bluff_pot, aggression, medium_max_price, draw_min_equity, cheap_price, max_call_stack_frac, preflop_max_price, big_bet_price, implied_pot_mult, all_in_frac. main.py умножает часть порогов на --aggression/--defense.
- Сейчас рейз почти всегда бьёт в ближайший живой пресет 33/50/75/100% банка (выбор пресета в table_state.bet_point по pot_frac).

ЗАДАЧА — реализовать по приоритетам. Что не успеешь — честно отметь в вердикте.

=== ПРИОРИТЕТ 1 (обязательно) ===

1. ПРЕСЕТЫ СТИЛЯ. Ключ 'style' в devices.json: 'tighty' | 'standard' | 'aggressive' | 'loose' (по умолчанию 'standard'). Каждый пресет = готовый набор настроек (aggression, defense, cbet_pot, nuts_pot, medium_max_price, big_bet_price, draw_min_equity, пороги блефа, размеры ставок). Сделай разумные дельты между пресетами (тайтовый: реже блефует, меньше коллит, меньше ставит; лузовый: наоборот; агрессивный: крупнее ставки, чаще блеф, но коллит как стандарт). Панель: выпадашка «Стиль» вместо/рядом с ползунками; выбор стиля перезаписывает связанные настройки, но отдельные ползунки (агрессия/защита) остаются поверх. Не ломай существующий devices.json (старые ключи работают).

2. НАСТРОЙКИ БЕЗ ПЕРЕЗАПУСКА. Бот должен перечитывать свой конфиг КАЖДОЕ РЕШЕНИЕ (не каждый кадр): panel.py сохраняет в devices.json → бот читает файл по своему --serial → применяет изменения (стиль, пороги, флаги). Файл маленький, чтение дёшево (кэшируй с mtime-проверкой, чтобы не читать на каждый кадр). panel.py: кнопка «Применить» + подсказка «применяется сразу». Убедись, что главный цикл main.py передаёт свежие настройки в strategy.decide (не только при инициализации).

3. РАЗМЕРЫ СТАВОК ПО УЛИЦАМ/СИЛЕ. Вместо «всегда ~50%»: натс — 75-100%, strong — 60-75%, medium/дро — 45-55%, и по улицам (на флопе можно крупнее, на ривере с натсом — максимум). Реализуй через настраиваемые ключи settings: 'bet_nuts' (0.75), 'bet_strong' (0.6), 'bet_medium' (0.5), 'bet_draw' (0.45) + множители по улицам 'street_factor_flop/turn/river' (по умолчанию 1.0). Всё по-прежнему выбирается ближайшим живым пресетом в bet_point (не трогай координаты!). Флаг вкл/выкл 'bet_sizing: on/off' (off = старое поведение).

4. МУЛЬТИПОТ (3+ в раздаче на постфлопе). Когда players >= 3: на тёрне/ривере не блефовать (воздух и слабые дро — чек/фолд), не ставить тонко на велью (medium — чек, strong — ставка, но меньше), коллить только по чётким пот-оддсам. Флаг 'multiway_tight: on/off' (по умолчанию on). В логах должно быть видно «мультипот N игроков — играем тайтовее».

5. КОРОТКИЙ СТЕК. Если stack_bb < порога (настраиваемый 'short_stack_bb', по умолчанию 30): префлоп — push/fold (алл-ин с премиум-диапазоном вместо мин-рейзов; колл алл-ина по пот-оддсам шире), постфлоп — топ-пара/дро играются на стек агрессивнее. Флаг 'short_stack_mode: on/off' (по умолчанию on). В логах — «короткий стек XББ — push/fold».

=== ПРИОРИТЕТ 2 (если хватит ресурсов) ===

6. БЛЕФ С БЛОКЕРАМИ. На ривере, когда у нас нет готовой руки, но наша карта блокирует натс-флеш/топ-стрит оппонента (у нас туз/король масти, где 3+ карты на доске), разрешить блеф с контролем частоты (не чаще ~1 из 3 таких ситуаций — счётчик в Bot). Флаг 'blocker_bluff: on/off' (по умолчанию off — консервативно).

7. ПОСТФЛОП-ПОЗИЦИЯ. OOP (мы первые/без позиции): medium на флопе — чек вместо конт-бета (если флаг), strong — ставка как обычно. IP: как сейчас. Флаг 'position_aware: on/off' (по умолчанию off).
