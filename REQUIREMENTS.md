# Требования (обновление ТЗ)

## 1. Максимум 6 игроков за столом (6-max)
Стол ClubGG может быть заполнен от 2 до 6 игроков (не только heads-up!).
- `table_state.py` должен корректно определять ЛЮБОЕ число игроков: 2, 3, 4, 5, 6
- Позиции: UTG, MP, CO, BTN, SB, BB (в зависимости от числа игроков)
- Очерёдность ходов должна учитывать полный круг (не только 2 игроков)
- Кнопка D (дилер) — определяет порядок: SB идёт после D по часовой стрелке,
  BB следующий, далее по кругу. На префлопе первым говорит игрок слева от BB
  (UTG), на постфлопе — первым слева от D (SB).
- Тесты: добавить сценарии для 3, 4, 5, 6 игроков
- Распознавание игроков: панели/аватары игроков вокруг стола, не только 2

## 2. Стратегия — внешние, загружаемые
Пользователь будет ИСКАТЬ и ЗАГРУЖАТЬ готовые покерные стратегии в проект.
Архитектура strategy.py должна поддерживать:

### Префлоп-чарты (стартовые руки)
- Файлы-чарты в формате JSON/CSV: таблица стартовых рук по позициям
  (UTG/MP/CO/BTN/SB/BB), например:
  ```json
  {
    "utg": ["AA", "KK", "QQ", "AKs", ...],
    "btn": ["AA", "KK", "QQ", "JJ", "TT", "AKs", "AQs", ...],
    ...
  }
  ```
- Разные наборы чартов (тайтовый, лузовый, стандартный 6-max)
- strategy.py должен УМЕТЬ ЗАГРУЖАТЬ чарт из файла и решать по нему:
  open-raise / fold / call по позиции
- Загрузка: `python strategy.py --load-chart charts/6max_standard.json`

### Постфлоп
- Базовая логика (по силе руки + пот-оддсы) остаётся, но должна читать
  настройки из загружаемого конфига (агрессия, размеры ставок)
- Возможность подменять правила без правки кода

### Формат
- charts/ — папка для чартов (загружаемых файлов)
- Пример чарта положить в charts/6max_standard.json
- README: как пользователь может добавить свой чарт
