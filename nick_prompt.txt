Ты — разработчик покерного бота для ClubGG (кэш NLH, Android, cv2 + табличная стратегия, БЕЗ ИИ в цикле). Код в ТЕКУЩЕЙ директории (/root/clubgg-bot — постоянная).

ЗАДАЧА — ЧТЕНИЕ НИКОВ ОПОНЕНТОВ.

ПРОБЛЕМА: сейчас оппоненты идентифицируются МЕСТОМ по кругу от героя («Оппонент 1», «Оппонент 2»). Когда игрок встаёт/пересаживается, места сдвигаются — тот же человек становится «Оппонентом 2», и на него создаётся НОВЫЙ профиль (дубликаты статистики). Нужно читать НИК с экрана и привязывать профиль к имени.

УСЛОВИЯ:
- На ПК пользователя (Windows) установлен Tesseract OCR 5.4: `C:\Program Files\Tesseract-OCR\tesseract.exe`, языки eng (+ rus скоро). На VPS tesseract НЕТ — тесты пиши с заменяемым вызовом (функция-обёртка, которую тест мокает), чтобы они проходили и без tesseract.
- Живые кадры 400px — в `shots_stack/` (32 шт, там видны плашки игроков с никами и суммами). На полном экране 1080x2400 — пропорции ×2.7. Герой всегда внизу слева (зона его стека уже есть: config.HERO_STACK_ZONE = (0.050, 0.8165, 0.275, 0.8378)).

СДЕЛАТЬ:
1. **Зоны ников.** На кадрах shots_stack/ определи, где у каждой плашки игрока находится НИК (текст над/под суммой). Плашки ищет table_state.find_player_panels (или найди зоны вручную по кадрам — герой внизу слева, оппоненты по кругу: справа, сверху, слева). Сделай конфиг-зоны: для каждого места (0=герой, 1..5 по кругу) прямоугольник ника в долях экрана. Учти: ники разной длины — зона с запасом, но чтобы не захватывать соседние элементы (флажок страны, сумму).
2. **Чтение ника.** Функция `read_nick(img, seat, tesseract=None) -> str | None` (в table_state.py или отдельный модуль nick_reader.py): вырезка зоны по конфигу → временный PNG (или stdin) → subprocess: `tesseract.exe <вырезка> stdout --psm 7 -l eng+rus` → очистка результата: trim, схлопнуть пробелы, убрать символы-мусор (|, _, • и т.п.), ограничить длину (ник до ~20 символов). Параметр `tesseract` — путь к exe (config.TESSERACT, по умолчанию 'C:\\Program Files\\Tesseract-OCR\\tesseract.exe'), None — функция возвращает None (режим без OCR). Ошибки subprocess — вернуть None, не падать.
3. **Привязка профилей.** В opponents.py: ключ игрока = прочитанный ник (нормализованный). Если ник прочитался — использовать его как имя профиля. Если None/пусто/мусор (доля «нечитаемых» символов высока) — fallback на текущее «Оппонент N (место)». **Слияние**: если на месте, где раньше копился профиль «Оппонент N», теперь прочитался ник — перенести накопленную статистику (hands, vpip, pfr, three_bet, agg) в профиль с ником и удалить/пометить старый (только если у «Оппонента N» нет других данных; аккуратно, не потерять).
4. **Периодичность**: ник читается раз в раздачу (там же, где update_stack/статистика), не каждый кадр. Кэш: не перечитывать, если seat пуст.
5. **Флаг 'read_nicks'** (по умолчанию on) в devices.json/панель: выкл — старое поведение (место).
6. **Панель**: блок «Оппоненты» показывает ники (уже есть, подставится автоматически).
7. **Лог**: при старте/обновлении «Оппонент на месте 3 → ник "PokerPro88" (статистика перенесена)»; «ник не прочитался — Оппонент 3 (место)».
